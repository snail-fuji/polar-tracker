# Инцидент: ночью запись ЭКГ прерывается через 1–2 часа

**Дата:** 2026-10-03
**Статус:** исправление внесено, ждёт проверки ночной записью

## Симптомы

- Днём запись идёт часами без перерывов, если трогать телефон хотя бы раз в 30 минут.
- Ночью, когда телефон долго лежит без движения, запись обрывается через час-два.

## Причина

Порог «раз в 30 минут» совпадает с тем, когда Android включает **Deep Doze**: экран выключен, телефон неподвижен примерно 30 минут и не заряжается. Днём телефон в этот режим не попадает, ночью попадает. В Doze проявились три слабых места.

### 1. Не было wakelock

`react-native-background-actions` запускает foreground service (`RNBackgroundActionsTask`, наследник `HeadlessJsTaskService`), но partial wakelock не берёт. `HeadlessJsTaskService.acquireWakeLockNow()` есть, но сам сервис его не вызывает (проверено по исходнику в `node_modules`).

Пока ремень присылает данные, каждый BLE-пакет будит процессор, и запись идёт. Если связь рвётся (повернулся во сне, ремень сдвинулся), пакеты перестают приходить и процессор засыпает. Таймер переподключения (`setTimeout`) в React Native работает через `Handler.postDelayed`, который отсчитывает время по uptime. Во сне uptime не идёт, поэтому таймер не срабатывает, пока что-нибудь не разбудит телефон.

Днём «что-нибудь» — это пользователь, поэтому днём всё восстанавливалось.

### 2. Переподключение сдавалось примерно через 3 минуты

`MAX_RECONNECT_ATTEMPTS = 10` с задержками 1, 2, 4, 8, 16 и 30 секунд. После десятой попытки статус становился `error`, и запись окончательно останавливалась. Если H10 пропадал дольше (например, терял контакт с кожей), сессия на этом заканчивалась.

### 3. Приложение не было исключено из экономии батареи

Многие прошивки (Xiaomi, Samsung, Huawei и другие) закрывают фоновые процессы даже при работающем foreground service, если приложение не в списке исключений.

## Исправления

| Что | Где |
|---|---|
| Нативный модуль `RecordingPower`: partial wakelock (`acquireWakeLock` / `releaseWakeLock`), проверка и запрос исключения из battery optimization | `app/android/app/src/main/java/com/anonymous/app/RecordingPowerModule.kt`, `app/native/recordingPower.js` |
| Регистрация модуля | `SafAppendPackage.kt` |
| Разрешение `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | `AndroidManifest.xml` |
| Wakelock берётся в `start()` до запуска FGS и отпускается в `stop()` | `app/ble/PolarService.js` |
| Переподключение без лимита для известного устройства: 6 быстрых попыток (`FAST_RECONNECT_ATTEMPTS`), затем `connectToDevice(id, { autoConnect: true })`. Android BT stack ждёт устройство бессрочно и не зависит от JS-таймеров | `PolarService._connectToKnownDevice`, `_scheduleReconnect` |
| Лимит попыток (`MAX_SCAN_ATTEMPTS = 10`) остался только для первого поиска, когда устройство ещё ни разу не найдено | `PolarService._scheduleReconnect` |
| При запуске приложение предлагает отключить для себя ограничения батареи | `App.js` |
| Лог соединения `polar_<ts>_log.csv` (`wall_time,status,message`): каждое изменение статуса с временем | `useSessionLogger.logStatus`, подписка в `App.js` |

### Попутно исправлено

- **Retry после ошибки не работал.** После `error` флаг `_stopped` оставался `false`, и `start()` сразу выходил. Теперь `start()` сначала вызывает `stop()` и сохраняет flush-callback, который `App` ставит до `startBle()`.
- **Двойное переподключение.** Один разрыв вызывал и `onDeviceDisconnected`, и ошибку подписки на данные, и оба запускали `_scheduleReconnect`. Теперь перед новым таймером старый сбрасывается (`clearTimeout`).
- **Остатки подписок.** `_setupDevice` теперь очищает подписки от прошлой неудачной попытки настройки.
- **Отмена ожидания.** `stop()` отменяет висящий `autoConnect` через `cancelDeviceConnection`.

## Как проверить

1. Пересобрать приложение (`npm run android` в `app/`) и в появившемся диалоге нажать «Разрешить».
2. Записать ночь и утром открыть `polar_<ts>_log.csv`:
   - **есть переходы `reconnecting` → `streaming`:** разрывы были, и приложение их пережило; исправление работает;
   - **лог обрывается без `idle`, уведомление пропало:** процесс убила прошивка. Нужно включить автозапуск и режим батареи «Без ограничений» в настройках производителя.
3. Без ожидания ночи Doze можно включить вручную:
   ```sh
   adb shell dumpsys deviceidle force-idle
   # проверить запись, снять ремень на несколько минут и надеть обратно
   adb shell dumpsys deviceidle unforce
   ```

## Цена

Wakelock держит процессор включённым всю сессию. На практике разница небольшая: поток ЭКГ 130 Гц и так будит процессор постоянно. Wakelock нужен в основном на время разрывов связи.

## Выводы

- Foreground service сам по себе не гарантирует, что процессор будет работать. Для долгой фоновой работы с таймерами нужен явный partial wakelock.
- JS-таймеры в фоне нельзя использовать как надёжный механизм. Для ожидания BLE-устройства лучше `autoConnect` на уровне Android.
- У долгой записи не должно быть жёсткого лимита попыток переподключения.
- Для фоновых сбоев, которые нельзя наблюдать вживую, нужен лог с временем событий.
